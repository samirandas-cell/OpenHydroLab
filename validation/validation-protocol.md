# OpenHydroLab — verification protocol

This document states what is verified, how the reference values are obtained, and what
tolerance each class of comparison is held to. It is the methods section for the
validation results in `results/validation-results.md`, which are regenerated by the
test run rather than transcribed by hand.

## Scope and limits

This protocol establishes **computational fidelity, reproducibility and adoption
readiness**. It says nothing about learning. No claim is made here about conceptual
understanding, engagement or achievement; those require a classroom study with human
participants and are outside this protocol entirely.

## Running it

```bash
npm install
npm run install-browsers
npm test
```

The run starts a local static server, exercises every laboratory in Chromium, Firefox
and WebKit, and writes the validation dataset to `validation/results/`.

## 1. Numerical verification

### 1.1 The reference must be independent

A test that recomputes the module's own arithmetic and compares it to itself proves
nothing. Every reference value comes from one of four sources, and the derivation is
recorded with the result:

| Source | Example |
|---|---|
| Closed-form analytical solution | Bélanger sequent-depth ratio; the Nash cascade response to a rectangular hyetograph |
| Conservation identity | specific force across a hydraulic jump; unit volume under a unit hydrograph |
| Hand-checkable textbook calculation | Manning discharge in a 5 m rectangular channel at y = 2 m |
| Independent reimplementation in the test harness | Gumbel method-of-moments fit recomputed in Node from the published annual maxima |

Where a module solves an equation by iteration, the test prefers a **round trip**:
compute the input from a known answer with an independent implementation, feed it back,
and require the original answer to return. Normal depth is verified this way.

### 1.2 Two independent routes to one number

Where a quantity can be reached by two different derivations, both are computed and
required to agree. These are the strongest tests in the suite because they fail if
*either* route is wrong:

- energy loss across a hydraulic jump, as `E₁ − E₂` and as `(y₂ − y₁)³/(4y₁y₂)`;
- a duration-changed unit hydrograph, by S-curve lag-and-subtract and by superposing
  lagged unit hydrographs;
- gradually varied flow reach length, by RK4 marching and by the direct-step method;
- the Rational Method discharge, as `C·i·A/3.6` and from base SI units.

### 1.3 Behaviour, not just values

Some claims the teaching rests on are orderings rather than numbers, and are tested as
such: urbanisation must raise and advance the storm peak; jump dissipation must increase
with Froude number; rainfall intensity must fall with duration and rise with return
period; a mild slope must give `yₙ > y_c`. These carry no tolerance — they either hold
across the swept range or they do not.

### 1.4 Sweeps, not spot checks

Conservation is not a property of one lucky parameter set. Volume closure, momentum
residual, the specific-energy identity and normal-depth inversion are each swept across
the control ranges (81 storm parameter sets, 81 channel states, 21 jump states, 9 gate
settings) and the **worst** error over the sweep is what gets recorded.

### 1.5 Tolerances

Tolerances are set by what the numerics can honestly deliver, and stated per case:

| Class | Tolerance | Why |
|---|---|---|
| Closed-form identity, no integration | 1e-9 relative | limited only by double-precision arithmetic |
| Bisection-solved root | 1e-6 relative | 60–80 bisection iterations on a bracketed root |
| Fixed-step integration (unit volume, GVF energy) | 1e-3 – 5e-3 | Δt truncation of the quadrature |
| Quantity read from a DOM readout | half a unit in the last displayed digit | the module rounds for display; the comparison cannot beat that |
| Empirical curve fit (Sherman IDF) | 10% RMSE, 25% worst point | a four-parameter surface cannot interpolate 36 quantiles exactly |

A tolerance is never widened to make a test pass without recording why in the case's
`source` field. Where a reference value is itself rounded — the published annual-maximum
table is given to four decimals — the tolerance states that bound explicitly.

## 2. Software verification

Run against all three browser engines:

- **Clean load** — no console errors, no uncaught exceptions, no failed requests, on
  every module.
- **Live rendering** — the canvas has real dimensions and `requestAnimationFrame` is
  actually driving frames. A blank canvas is the commonest silent failure and produces
  no error of its own.
- **Self-containment** — no module may request anything outside its own origin, checked
  both at run time and by scanning the source for third-party hosts. This is what makes
  the offline claim testable rather than asserted.
- **Offline operation** — every external host is blocked and each module must still
  initialise, which is the honest simulation of a student opening the file with no
  connection.
- **The `file://` protocol** — every module is additionally loaded straight from disk, with
  no server at all, and must initialise, render and animate exactly as it does over http.
  This duplicates the checks above on purpose. Serving over `http://localhost` is a
  materially different environment from double-clicking a file: browsers block ES-module
  imports from a `file://` origin under CORS while permitting them over http, and a
  regression of exactly that kind once shipped past a suite that only ever used a server.
  Since the primary distribution route for these laboratories is "download the file and
  open it", the protocol students actually use has to be the protocol under test.
- **Link integrity** — every internal link on the landing page resolves.
- **Documentation coverage** — every laboratory has a written guide in `docs/`.

## 3. Accessibility

- Every interactive control has an accessible name, computed through `aria-label`,
  `aria-labelledby`, an associated `<label>`, wrapping label, text content or `title`.
- Range sliders respond to arrow keys, and the on-screen readout updates when they do —
  a slider that only moves under a mouse locks out keyboard and switch users.
- Tab order reaches the controls without a pointer.
- No horizontal overflow at 1920×1080, 1366×768 and 1024×768.

## 5. Known gaps

Recorded here rather than hidden, because a validation protocol that only reports
successes is not evidence of anything:

None open. The whole suite passes on Chromium, Firefox and WebKit.

This section exists to be filled in, not to stay empty: anything the suite cannot
currently establish belongs here rather than in a footnote.

### Closed

- **Two laboratories had no written guide** — `specific_energy` and `hydraulic_jump`.
  Both are now in `docs/`, and the documentation-coverage test passes for all eight
  modules.

- **`channel_geometry` loaded Three.js from a CDN**, so it was neither self-contained nor
  usable offline. Three.js r160 is now vendored under `animations/vendor/three/`
  (see the README there for provenance) and the self-containment and offline tests pass
  on all three engines. The module is no longer a single file: it is a page plus its
  vendored library, and the project's wording was corrected accordingly.
- **`channel_geometry` physics could previously be verified only through its DOM
  readouts**, because the whole module lived in ES-module scope. It is now split: the
  physics is a classic script in the global scope and the Three.js rendering stays an ES
  module. All eight laboratories are therefore verified at machine precision, and the
  readout comparison has become a separate, explicitly-labelled presentation test rather
  than the only available evidence.

## 6. A note on tolerances that are not machine precision

Three groups of cases sit well above 1e-9, and in each the reason is a property of the
mathematics rather than a defect. They are listed here because a protocol that quietly
widens a tolerance is not evidence of anything:

- **The 1/7-power velocity profile** (`CG-09.power.*`, ~3×10⁻⁴). `u = (8/7)ξ^(1/7)` has an
  unbounded derivative at the bed, so Simpson's O(h⁴) bound does not apply and
  convergence falls to roughly O(h^(8/7)). The uniform and linear profiles, whose
  integrands are polynomials of degree ≤ 3, are exact to machine precision — which is
  what confirms the quadrature itself is right.
- **Fixed-step integration** (unit-hydrograph volumes, the GVF energy integral, storm
  volume closure), where the residual is Δt truncation and shrinks on refinement.
- **The Sherman IDF fit**, which is a four-parameter surface summarising 36 Gumbel
  quantiles and cannot interpolate them exactly. Its tolerance is stated as a fraction of
  the mean intensity being fitted.
